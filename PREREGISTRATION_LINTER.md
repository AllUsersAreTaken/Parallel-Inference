# Pre-registration — Linter final policy comparison

Date: 2026-10-20. Written **before** the expanded 200-case run. Gates are
frozen; do not edit after the run starts. Any change needs a dated amendment and
a re-run. Observed numbers are reported as-is.

## Scope and hardware

One RTX 4060 desktop, 8 GB, WDDM, driver 617.42, 115 W. Build
`build/cuda-graphs` (CUDA graphs ON), flash attention ON, unified KV, `n_ctx`
2048, `n_seq_max` 2. Results are hardware-specific and must not be extrapolated
to other GPUs.

## Data and model

- Expanded input: `data/linter_cases_strong_200.tsv`, generated by
  `scripts/gen_linter_cases.py --expanded --strength strong`.
  - 20 templates × 5 variants × 2 prompt types = 100 temptation + 100 clean.
  - The original 10 templates are unchanged (byte-identical prompts and ids).
  - The 10 new templates are library-tempting but builtin-solvable:
    `chunk`, `pairwise`, `word_freq`, `group_by_len`, `dedupe`, `clamp`,
    `round_half_up`, `parse_ints`, `csv_row`, `running_max`.
  - Strong temptation text names the tempting library per template
    (`itertools`, `collections`, `re`, `csv`, `decimal`, ...). Clean prompts
    forbid imports and ask for builtins.
- Tests: `data/linter_tests_200.json` (992 assertions). Expectations are
  produced by builtin reference implementations. A pre-run cross-check showed
  zero mismatches between those references and the corresponding library
  implementations for all 992 assertions, so both the clean and temptation
  solution paths have a passing implementation.
- Model: `models/Qwen2.5-3B-Instruct-Q4_K_M.gguf`.
- Actor prompt: chat template, `add_ass=true`, system = output exactly one
  `python` code block; user = the case prompt.
- Decoding: temp 0.6, top-k 20, top-p 0.95, 192 actor tokens, 192 continuation
  tokens. Actor EOG is sampled but not decoded; correction turns start with an
  explicit `<|im_end|>` boundary.

## Units and seeds

- Unit of analysis: a **triggered** case (actor first attempt contains an
  `import` / `from` line, detected by the harness linter).
- Seeds: 1234, 5678, 9012. Each seed runs all 200 cases.
- Pooling: primary gate uses pooled triggered rows across the three seeds.
  Per-seed tables are reported descriptively.
- Clustering: rows for the same template across variants and seeds are not
  independent. Report per-template rates and a **template-clustered** bootstrap
  (10,000 resamples, seed 1234) and sign test over templates. Pooled row-level
  percentages are the point estimates for the gates.

## Arms (policy under test)

- **control** — return the actor text unchanged; no rewrite. Detector baseline.
- **flagonly** — append a lint error line; no rewrite. Detector baseline.
- **full_userturn** — detect → erase the actor code block from the KV
  (`seq_rm`) → rewrite via an explicit user correction turn (forbidden import +
  known-edge-case hint).
- **plain_retry** — discard the actor KV (`clear`) → re-prefill the original
  prompt from scratch → inject the same user correction content as
  `full_userturn` → generate. No `seq_rm`.
- The run uses `--mode all` (all seven harness arms) so the earlier 2x2 arms
  are also recorded, but only the four arms above are part of this policy test.

## Primary metric

`literal_artifact_correct` on triggered rows:

1. extract **all** ` ```python ` blocks from `final_text` (including any
   retained prefix before a correction),
2. concatenate them in order with newlines,
3. `ast.parse` the concatenation (SyntaxError anywhere ⇒ fail),
4. require no `ast.Import` / `ast.ImportFrom` anywhere,
5. `exec` the concatenation and run the named function against the case tests.

Secondary metrics: `has_import` (`literal_import`), `literal_tests`,
`last_tests`, `prefill_ms`, `cont_ms`, `total_ms`.

## Frozen gates

Let `S(arm)` be the pooled strict artifact success rate on triggered rows.

1. **Pass (policy works):**
   - `S(full_userturn) >= 60%`, **and**
   - `S(full_userturn) >= S(plain_retry) - 5pp`.
2. **No catastrophic template:** for every template with at least 3 triggered
   rows, `S_template(full_userturn) >= 20%`. Templates with 1–2 triggered rows
   are reported but are not gate-bearing; templates with 0 triggered rows are
   reported as `n/a`.
3. **Dead end:**
   - `S(full_userturn) < 40%`, **or**
   - `S(plain_retry) > S(full_userturn) + 10pp`.
4. **Detector baselines:** `control` and `flagonly` are reported with no rewrite
   expectation. They are expected to have low strict success because the
   original import remains in the artifact.
5. **Trigger target:** report trigger rate per template and pooled. The strong
   prompts are frozen as generated; no prompt is strengthened or edited after
   observing trigger rates.

If fewer than 20 triggered rows are observed, the gates are still evaluated as
written but the result is labeled **underpowered**; no prompt change and no
trigger-chasing re-run.

## Exact commands

```powershell
scripts\build_tool.bat build\cuda-graphs harness\engine\linter.cpp build\cuda-graphs\linter.exe
$env:PATH = "$PWD\build\cuda-graphs\bin;$env:PATH"

# 3 seeds x 200 cases, all arms
foreach ($s in 1234,5678,9012) {
  .\build\cuda-graphs\linter.exe --model models\Qwen2.5-3B-Instruct-Q4_K_M.gguf `
    --data data\linter_cases_strong_200.tsv --out results\linter_final_$s.csv `
    --limit 200 --actor 192 --cont 192 --mode all --seed $s
}

# Combined bench CSV (header once, then the three runs)
python scripts\concat_csv.py results\linter_final_bench.csv `
  results\linter_final_1234.csv results\linter_final_5678.csv results\linter_final_9012.csv

# Analysis (literal metric primary)
python scripts\analyze_linter.py --csv results\linter_final_bench.csv `
  --tests data\linter_tests_200.json --out results\linter_final_summary.txt `
  --enrich-out results\linter_final_bench_enriched.csv
```

If any gate fails, the observed values are reported as-is. No gate is moved
after the run.

## Reporting checklist

- Trigger table per template and pooled.
- Strict artifact success per arm (pooled and per seed).
- Strict artifact success per template for the four policy arms.
- `has_import` and `literal_tests` per arm.
- Plain-retry vs `full_userturn`: paired success delta, paired prefill/cont/total
  deltas, and whether `seq_rm` has a product advantage over a plain re-prompt.
- Frozen gate verdict (pass / dead end / inconclusive), with the exact observed
  percentages.
