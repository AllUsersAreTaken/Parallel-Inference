## Session findings (2026-10-19)

All five angles were tested with real runs and audited. **No defensible accuracy win emerged.** The
consistent picture:

1. **Selection, not sampling, is the bottleneck.** C8 vs oracle@8: 1B 57.5 vs 79.0 (n=200, m6);
   coder15b 72.5 vs 86.0; 1.5B distill 80.0 vs 91.5 (n=200, dev200_s16). When the plurality is wrong,
   the gold answer usually has support 0 or 1 (dev200: 17/40 at 0, 13/40 at 1), so a selector must pick a
   minority answer — the model's own audit cannot (angle 2).
2. **Mechanisms that genuinely decorrelate vs do not.** Code vs CoT errors are decorrelated
   (wrong-answer Jaccard ~0.10-0.12) and the union raises oracle coverage by +2-4 pts, but code is
   individually weaker, so the vote does not improve. System-prompt personas are ignored; in-context
   exemplars hurt via format/content priming.
3. **Batch composition/layout is a first-order confound.** Identical prompt+seed+slot streams change
   text on 5-23% and answers on 42-58% of problems depending on co-resident streams; accuracy moves
   5-13 pts. This produced the apparent m3 (+8) and s4 (+7.5) gains and is why the within-batch tests
   (angle 1b, 5) reversed them. **Future A/B work must be within-batch or multi-seed.**
4. **Coverage is the real asset.** The union of cot + code streams solves 98% of coder15b and 90% of 1B
   problems (vs 94% / 86% for cot alone). The missing piece is an objective selector, not more samples.

**Recommended next angle:** use an objective selector. (a) For code, generate N programs in one batch
and select with unit tests (needs HumanEval/MBPP); (b) or use a 3B local model as a selector on the 1B's
candidates, compared against the 3B generator alone. Both are outside this session's compute/model set.
